# 0.4.10 · 模型自主选择与审查报告恢复

模型型号、档位和子模型设置现在都是可选建议，由各 Agent 按自己的客户端规则和任务需要决定。工作台不要求 Agent 自报或证明型号，也不因型号缺失、名称不同或未列入目录而拒绝接单和成果。

- 执行、审查、收尾和子代理回执取消型号一致性门槛。模型信息能取得时记录，无法取得时保留未知。
- 模型建议可留空，也可输入目录外的名称。留空使用客户端自己的默认配置；清空原有建议不会恢复旧型号。
- Grok 官方记录的所选型号与回答型号不同（例如 `grok-4.7` 与 `grok-4.7-build`）时，可以接收原审查报告。原始结论、问题和限制保持不变。
- 工作台保存的原生调用仅因旧型号检查失败时，可恢复其已完成报告，不重新启动模型。原失败记录保留。
- 规划资料、执行单、审查提示词和当前手册统一说明模型自主选择；旧执行单中的型号限制不再执行，历史文件保持原样。

任务、会话和交付版本仍对应真实记录。模型自主选择不会把“需要修改”改成“通过”，也不会代替用户试用验收。

## 公司电脑更新与原报告重试

先安装本版并确认工作台版本为 0.4.10。由当前项目 Agent 读取原任务的最新状态：官方 Grok 会话使用原 `session_id` 重试 `submit_grok_review`；工作台发起并已保存完整原生输出的调用使用原 `job_id` 调用 `recover_native_review`。不要为了补登记再次启动审查模型。

重试必须针对原报告绑定的交付版本。若内容已变更，保留旧报告并处理新内容。公司报告原有三项修改意见应继续登记为需要修改，本次更新仅解决报告接收问题。

发行内容包括正式源码、Windows 便携程序和 SHA256 校验文件。更新会保留业务数据与安装前程序备份。
