# v0.4.9 更新说明

这次更新让提需求、交接和试用确认更直接，并包含 v0.4.7、v0.4.8 的协作流程改进。

## 提需求

- 项目选择只展示正在进行的项目。当前打开的项目优先；其他入口记住最近访问或提交过需求的项目，不再默认选刚创建或刚修改资料的项目。
- 需求描述写在一处。重要程度、规划方式、成果与使用位置、审查安排直接可见。
- 成果可以沿用项目设置、根据这次需求交给大脑安排，或由你指定。继承的设置与明确选择分别记录，通用默认值不会在“由大脑安排”时锁死交付方向。
- 旧需求中已填写的期望结果、完成标准和特殊交付要求继续保留并可编辑。
- 复制给 GPT 普通聊天或规划 Agent 的资料包含项目摘要：当前任务、阻碍、最近交付与验收、来源和时间。登记阶段与实时进展分别显示，不附送完整旧对话。

## 试用与交接

- 首页“去试用确认”直接打开确认框，显示项目、任务、成果和确认项。确认、退回和稍后再说始终位于弹窗底部，不必滚到内容最末尾。
- 成果可在工作台预览，再回到原来的确认框。确认项由你亲自勾选。
- 任务列表可以直接复制当前执行单；剪贴板不可用时显示完整文本供手动复制。复制仍与派发、接单分别记录。

## 同会话协作

- 审查成员可以增加、移除和替换。各自的状态、报告和负责人决定保留在同一任务中。
- 当前执行者可在本会话继续派审、处理返修和收尾，无需用户反复转单。外部主执行首次启动和更换负责人仍由用户掌控。
- 执行者或审查者可以按用户口述办理绑定项目的资料和安排变更，保留来源和修订记录。独立报告仍由真实审查者提交；用户验收由用户完成。
- 项目经验先查看短索引，再按相关条目读取；同会话复用已读内容，只补变化。

## 更新与回退

从正式 Release 下载完整 Windows 便携包；已安装的便携版可在“设置 → 软件更新”下载并重启更新。含 `.git` 的开发工程沿用开发安装流程。

本版没有新增数据库迁移编号。安装前保留程序和数据备份；更新保留项目账本、执行历史、连接配置和密钥。回退使用安装前程序及对应数据备份。操作方法见 [检查与安装更新](UPDATES.md)。

用量仍按实际接入来源记录；未观测的模型身份、会话或 Token 不补成估计的实测值。网页负责保存与流转，规划仍由真实模型完成。
