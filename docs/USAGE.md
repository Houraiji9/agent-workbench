# 使用与维护

## 常用操作

“今天”聚合需要处理的任务；“项目”保存需求、成果、图解和上下文；“团队”管理工具与各自队列；“额度”管理采集数据和手填值；“记录”检索执行会话。

提需求时先选择项目。“先记下来”可以继续编辑、删除或稍后开始；“现在开始”进入待规划。复制衔接内容给 Codex 后，由它读取上下文、制定计划并生成执行单。把执行单发给指定 Agent，收到 started 回报后才算接单。

完成后先做 Review，再由自己确认使用效果。看不满意时选择“不通过”，写出希望修改的内容，再复制返工指令。旧成果和审查记录会保留。

项目可归档并在归档列表恢复。团队成员、订阅计划、已登记订阅和自定义额度都可以编辑；涉及正在执行的任务时，先结束或改派任务。

## 运行与移动

便携包完整解压到当前用户可写位置，双击 `桌面版/工作台/工作台.exe`。工作台在 127.0.0.1:4317 提供本机页面，由桌面窗口打开。关闭窗口会退出，最小化会留在托盘。

移动程序时关闭后移动完整文件夹。已经登记的项目和执行包存有绝对路径，移动这些资料需重新核对项目路径，或在原位置保留项目。不要同时运行两份程序操作同一 data。

## 备份与恢复

设置中点击创建备份，保存返回的文件夹。也可在源码环境运行 `npm run backup`。备份包含账本、成果副本、执行包及内部凭据；项目源代码和外部工具原始会话需另行保管。

恢复前关闭工作台，选择一个尚不存在的新目录：

```powershell
npm run restore -- 'C:\Backups\WorkbenchBackup' 'C:\Restored\WorkbenchData'
$env:WORKBENCH_DATA_DIR='C:\Restored\WorkbenchData'
.\启动工作台.ps1
```

以上均为示例路径。恢复工具校验归档 hash、重建执行包入口；原 cwd 保留，请确认源项目仍在。恢复失败时保留 RESTORE_INCOMPLETE 标记，不要手动删除标记后使用不完整数据。

## 排错

- 端口占用：先关闭另一份工作台或开发后台。不会为了启动而杀掉无关进程。
- 外部数据未连接：Token Monitor 默认 local 模式没有 HTTP 服务。推荐双击根目录“连接Token Monitor.cmd”；已有服务方案需开启 Host 并重启。详见 [连接说明](INTEGRATIONS.md)。
- 额度停止更新：查看来源时间；离线缓存会保留，可按需手动核对。
- 无法打开成果目录：文件可能已移动，使用“打开归档文件夹”查看已保存副本。
- 页面太小：Ctrl 与加号/减号缩放，Ctrl+0 恢复自动大小。
- 启动报错：查看本机 data/desktop-server.log 与 data/desktop-lifecycle.jsonl。分享日志前移除私人信息。

配置示例在 config/example.json。复制为 config/local.json 后按需填写端口、时区和集成；authorizedRoots 留空表示需要在页面显式登记项目，不要填整盘根目录。

## 从 v0.1.0 升级到 v0.1.1

1. 在设置里创建私人备份，并退出工作台。若单独启动过工作台的数据服务，先运行旧版 scripts/停止数据服务.ps1。
2. 下载并核对 v0.1.1 便携包的 SHA256，解压到一个临时文件夹。
3. 将新包里的程序文件复制到原工作台目录，覆盖同名程序文件，保留原路径。新包不包含 data、config/local.json 或 .agent-workbench；保留这三处原有内容。
4. 从原目录打开工作台，检查项目、任务和额度。原已接通的 Token Monitor 配置可继续使用，无需再次运行连接工具。

升级包不带破坏性数据库迁移。不要用空文件夹替换整个 data，也不要将旧 data 上传到问题反馈中。需要回退时关闭工作台，用 v0.1.0 程序文件配合升级前备份恢复。
