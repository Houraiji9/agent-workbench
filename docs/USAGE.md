# 使用与维护

## 常用操作

“今天”聚合需要处理的任务；“项目”保存需求、成果、图解和上下文；“团队”管理工具与各自队列；“额度”管理采集数据和手填值；“记录”检索执行会话。

提需求时先选择项目。“先记下来”可以继续编辑、删除或稍后开始；“现在开始”进入待规划。复制衔接内容给 Codex 后，由它读取上下文、制定计划并生成执行单。把执行单发给指定 Agent，收到 started 回报后才算接单。

需求箱沿用右上角统一的“提需求”按钮。额度页把快重置、又剩得多的周额度排在前面，余量 ≤15% 的降低优先级；例如剩 80%、两天后重置，排在剩 20%、几小时后重置之前。Antigravity 三组独立判断，Grok 周额度也参与。相同优先级继续按卡片大小排列，页面随时间和新数据自动调整。

执行单较多时，打开“项目 → 进展 → 执行顺序”，按步骤处理标为“可执行”的任务。“等待前序”会列出要先完成的任务，点击名称就能查看；前序验收后，后续任务自动解锁。团队成员详情中的“执行队列”按建议第 1 单、第 2 单排列。同一步表示相同阶段，具体并行安排由 Codex 根据任务与项目路径判断。

首页、需求箱和项目中的长需求默认显示两行。点击“查看全文”阅读或复制全部内容；编辑和规划仍使用完整需求。

完成后先做独立审查，再把收尾单交回执行者完成剩余事项；收尾完成后，由自己确认使用效果。看不满意时选择“不通过”，写出希望修改的内容，再复制返工指令。旧成果和审查记录会保留。

也可以在 Agent 会话中交代修改需求、团队、额度或订阅。验收、退回等关键决定会预填到首页确认卡，你点一次即可。详细入口见 [会话管理](CONVERSATION_MANAGEMENT.md)。

项目可归档并在归档列表恢复。团队成员、订阅计划、已登记订阅和自定义额度都可以编辑；涉及正在执行的任务时，先结束或改派任务。

## 运行与移动

便携包完整解压到当前用户可写位置，双击 `桌面版/工作台/工作台.exe`。工作台在 127.0.0.1:4317 提供本机页面，由桌面窗口打开。最小化留在任务栏；关闭窗口隐藏到右下角托盘，后台继续运行。需要彻底退出时，右键托盘选择“退出工作台”。

移动程序前先从托盘彻底退出，再移动完整文件夹。已经登记的项目和执行包存有绝对路径，移动这些资料需重新核对项目路径，或在原位置保留项目。不要同时运行两份程序操作同一 data。

## 备份与恢复

设置中点击创建备份，保存返回的文件夹。也可在源码环境运行 `npm run backup`。备份包含账本、成果副本、执行包及内部凭据；项目源代码和外部工具原始会话需另行保管。

恢复前从托盘退出工作台，选择一个尚不存在的新目录：

```powershell
npm run restore -- 'C:\Backups\WorkbenchBackup' 'C:\Restored\WorkbenchData'
$env:WORKBENCH_DATA_DIR='C:\Restored\WorkbenchData'
.\启动工作台.ps1
```

以上均为示例路径。恢复工具校验归档 hash、重建执行包入口；原 cwd 保留，请确认源项目仍在。恢复失败时保留 RESTORE_INCOMPLETE 标记，不要手动删除标记后使用不完整数据。

## 排错

- 端口占用：先关闭另一份工作台或开发后台。不会为了启动而杀掉无关进程。
- 外部数据未连接：Token Monitor 默认 local 模式没有 HTTP 服务。推荐双击根目录“连接Token Monitor.cmd”；已有服务方案需开启 Host 并重启。详见 [连接说明](INTEGRATIONS.md)。
- 额度停止更新：查看来源时间；离线缓存会保留，可按需手动核对。
- 无法打开成果目录：文件可能已移动，使用“打开归档文件夹”查看已保存副本。
- 页面太小：Ctrl 与加号/减号缩放，Ctrl+0 恢复自动大小。
- 启动报错：查看本机 data/desktop-server.log 与 data/desktop-lifecycle.jsonl。分享日志前移除私人信息。

配置示例在 config/example.json。复制为 config/local.json 后按需填写端口、时区和集成；authorizedRoots 留空表示需要在页面显式登记项目，不要填整盘根目录。

## 手动升级到 v0.1.6

1. 在设置里创建私人备份，并从托盘选择“退出工作台”。若单独启动过工作台的数据服务，先运行旧版 scripts/停止数据服务.ps1。
2. 下载并核对 v0.1.6 便携包的 SHA256，解压到一个临时文件夹。
3. 将新包里的程序文件复制到原工作台目录，覆盖同名程序文件，保留原路径。新包不包含 data、config/local.json 或 .agent-workbench；保留这三处原有内容。
4. 从原目录打开工作台，检查项目、任务和额度。原已接通的 Token Monitor 配置可继续使用，无需再次运行连接工具。

旧版可按此步骤升级；v0.1.4 起也可在设置中检查、下载和安装后续版本。v0.1.6 新增收尾、管理回执与用户确认事项迁移，并移除外部订阅镜像；个人登记的订阅保留。已验收任务保持原状，未验收的审查通过任务补入收尾流程。新包的两个更新清单也需复制，详见 [更新与恢复](UPDATES.md)。保留原有 .codex 项目配置。需要回退时从托盘退出工作台，用原版本程序文件配合升级前备份恢复。

## 临时文件集中处理

维护完成后，不再需要的测试目录、调试日志和旧打包目录统一移到项目根的“待清理”，其中保存原路径与新路径清单。正式 data、有效执行包、归档成果和当前程序保留原位。开发者移动含目录链接的测试夹具时，应使用同盘目录重命名，不递归跟随链接移动目标依赖。
