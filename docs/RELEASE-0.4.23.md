# 0.4.23：协作收尾与状态连续性

修复跨 Agent 协作中“整合版本已经审查上线，协作任务仍卡在中间状态”的入口缺口，并处理同类状态倒退。

- 仅追加说明或证据引用使用 `manage_tasks.append_note`。记录实际办理者，保留任务状态、交付、审查和收尾。真正修改目标、范围或验收条件仍使用 `amend`，受影响交付重新核对。
- 整合负责人使用 `manage_tasks.complete_integrated_closeout`，一次明确指定整合主 Run 与协作 Run，记录双方交付指纹、审查和部署事实、文件覆盖及未验证项，完成目标任务的收尾。保留原执行者和审查者身份，不复制主单的“通过”作为子单审查，也不自动关闭其他依赖。
- 收尾上下文读取为纯查询。没有收尾时返回预览，正式提交时创建记录；完成请求重放先检查幂等，避免返回成功却重置状态。
- 实质范围变更或明确重新收尾后，生成独立收尾编号与报告文件，历史报告及其指纹保留，避免覆盖先前已完成的证据。
- 交付后的迟到进展、阻碍和收尾回报保存事实与序号，不把已提交、待试用、已结束任务倒退到运行中，也不覆盖完成报告。明确的新交付和实质范围变更继续保留原有版本流转。
- 同一交付追加、替换、移除或撤回审查，保留已完成收尾。补审结论与未验证事项分别展示；明确返工决定才重新进入返修。已结束任务的晚到本人审查按历史记录保存。
- 任务详情展示原交付与实际整合收尾身份，提供主单跳转、证据折叠和备注历史。待试用状态清楚指向用户，部署缺口作为独立技术提示。
- 按任务读取管理上下文不再夹带全部任务正文；接口与帮助说明分别引导补注、范围修订、本人收尾和整合收尾。

工作台记录真实执行、审查、部署及收尾事实；用户最终试用验收仍由本人确认。说明性备注不等于核验通过。公司电脑已有任务不会根据标题或依赖自动批量改状态；当前会话可以明确指定任务，通过正式接口继续办理。
