# v0.4.6：项目管理、用量与可控执行

本说明汇总 v0.2.1 以来的功能变化与升级要求。可下载版本以 GitHub 正式 Release 为准，设备是否完成更新以实际版本和安装记录为准。

## 今天、需求箱与项目

- 今天页按需要做的动作分组，待安排的例行事项采用紧凑行，复制入口直接可见；需求名称和需求箱保持一致。
- 需求箱把每条需求的主操作集中呈现，保留完整原文、查看、复制和编辑。项目筛选跟随地址，侧栏返回、前进后退和刷新保持一致。
- 项目页集中显示说明、阶段和任务进展，按页签查看文件、用量、流程、图解与记忆。“更多”菜单的动作或对话框结束后，键盘焦点回到菜单按钮。
- 项目可以“收纳并暂缓新安排”。当前已运行的调用继续，后续新安排暂停；恢复后保留原任务和历史。
- 项目文件分别记录用途、有效性和保留状态。分类不会移动文件；移入待清理需要逐项说明与确认，保留移动和恢复记录。未知来源不等于文件无用。

## 项目用量与过程

Token Monitor 的项目会话用量和工作台调用账本分别展示，两者可能重叠，不能相加。仅通过明确的项目、Run、原生会话或完整工作目录关联归属；不会按项目名称猜测，也不自动分摊跨项目或多设备歧义记录。

新输入、输出、缓存读取和缓存写入分别统计。缺失指标保持未知；API 等价估价不代表订阅实际扣款。离线时保留最后有效快照与采样时间。旧版已结束调用只有合法整次摘要且没有逐事件账本时，才补为只读历史小计，不重写原始记录，也不声称已完整采集。

## 交付与需求重要程度

交付档案区分成果类别与使用位置：可以交付源码、软件、服务、文档或媒体，也可以明确本机、线上等部署目标。规划者可以补齐安装、健康检查和回退方法，但不能静默改变用户指定的目标或方法。

工作台便携程序使用安装清单核验受审版本；其他部署记录明确标为执行者报告，不冒充工作台已连接远端完成核验。审查、部署、执行者收尾和用户试用分别记录，生成候选不等于安装完成。

普通需求优先选择能力够用的经济模型；重点需求要求规划者明确比较当前可用模型，并为主执行、子代理和独立审查选择符合要求的模型。资源不足时停止并重新规划，不自动降档。任务大小、需求重要程度和聊天规划方式分别选择；普通 GPT 聊天的小需求规划入口最多提交三项任务。

## 客户端发现与 Cursor

Windows 刷新检测会重新读取用户和系统保存的 PATH，不修改全局环境变量。客户端路径与检测缓存只保留在本机，换电脑后重新发现。

Cursor Agent CLI 的 Windows 启动文件经过已知格式核验后，工作台使用安装目录里已有的固定版本入口检查帮助与版本，不为识别客户端执行更新脚本。未知格式、缺失文件或越界链接保留未验证状态。当前 Cursor 接入用于只读独立审查，必须确认支持 plan 模式；不启用强制写入权限。

发现客户端、登录、额度、实际调用和真实结果是不同事实。检测成功不证明账号或模型可用；没有可靠来源时保留未知。

## 执行安排与启动控制

任务详情可修改执行者、主模型和子代理。尚未生成执行单时直接采用；执行单已生成但未接单时，保留旧单并重新生成；执行中保存为下一版安排，不热切换正在运行的客户端；失败或需要修改时可生成下一版。每版 Run 的模型、范围和权限冻结留档，旧交付与审查保留，用户选择优先于规划建议。

启动控制与执行安排分别保存：

- 外部主执行默认由用户启动；修改安排只保存安排，不等于启动。
- 自动返修和收尾必须由用户在“执行安排 → 启动方式”单独开启，并符合任务已有计划。规划、交付、审查结束或中断恢复本身不构成启动授权。
- 用户已授权当前 Agent 会话继续工作时，执行者可以按自己的正式 Run 本人接单与回报；这不等于工作台启动了另一个客户端。
- 独立审查和已授权的白名单子代理按本任务约束调用，保留各自身份、范围、调用与结果。停止和中断不会被伪装成已完成工作，未确认结束的原进程仍阻止新调用。

## 子代理入口

执行者可通过本 Run 的固定 `register-delegation` 和 `report-delegation` 入口登记允许的模型、读写范围、产物、并发和次数，并报告真实会话与结果。管理入口和执行者入口各自保留权限边界，登记不等于实际启动。

主执行者负责整合子代理结果，作者自己的子代理不能代替独立审查。原生客户端内部的子代理仍主要通过指令约束；工作台不承诺操作系统级隔离、强制拦截或完整观测。Token 预算是提醒值，不是硬性封顶。

## 升级、备份与回退

从 v0.2.1 升级涉及两份新增迁移：

| 迁移 | 内容 |
| --- | --- |
| 013 | 客户端调用记录及按 Run、请求编号检索的索引 |
| 014 | 用量事件、项目文件、文件移动和委派记录及相关索引 |

v0.4.6 本轮整理没有另外增加迁移编号。已执行的迁移不会重复创建历史记录；旧 Task、Run、Review、执行包与用户验收仍保留各自事实。

1. 安装前创建完整备份，并保留上一版本程序。备份含账本、配置、执行包及凭据，放在私人位置。
2. 从正式 Release 获取完整便携包并核对 SHA256；保持原安装位置，按更新流程替换程序文件，保留 `data/`、`config/local.json`、`.agent-workbench/` 等本机内容。不能只替换 EXE。
3. 安装后核对实际版本、受管文件清单、项目和任务记录以及外部连接配置；源码构建或打包成功不代替这些检查。
4. 若需回退，使用旧程序与升级前的完整数据备份，不让旧版本直接打开升级后的数据库。保留现场和回退记录，避免混用新旧程序文件。

应用内更新只读取 GitHub 正式 Release；仅推送源码不会让安装端发现新版本。源码工程继续通过 Git 和开发构建流程更新，不使用便携更新覆盖开发工作树。完整操作与限制见 [更新说明](UPDATES.md)。

独立审查、安装与发布结果分别保存在对应 Run、RA、安装清单和 GitHub Release 中；功能说明不代替这些记录，用户试用验收仍由用户本人完成。
