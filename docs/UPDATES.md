# 检查与安装更新

当前更新内容见 [v0.4.9 更新说明](RELEASE-0.4.9.md)：提需求与最近项目、带项目摘要的聊天规划、直接试用确认，以及同会话与多人审查协作。

## 日常更新

从 v0.1.4 起，打开桌面工作台的 **设置 → 软件更新**：

1. 点“检查更新”，查看新版本及更新内容。
2. 点“下载新版”。下载期间可以继续使用工作台。
3. 保存正在填写的内容，点“重启并更新”，再确认“现在重启更新”。工作台会退出，安装后重新打开。

更新只来自本仓库的 GitHub 正式 Release。检查与下载由你主动发起；没有定时后台下载。网络不通时可以稍后重试。

更新替换程序文件，保留 `data/`、`config/local.json`、`.agent-workbench/`、`.codex/` 和程序目录之外的项目。数据库会在安装前另存一份。请把自己的项目放在独立文件夹，程序的 src、docs、scripts 等目录会随版本更新。

程序须放在当前用户可写的普通文件夹内。含目录链接、数据路径与程序目录重叠、源码 Git 工作区等情况使用开发流程更新。安装前请结束另外单独启动的工作台服务；本次桌面启动的后台和数据服务会自动退出。

## 从 v0.1.0—v0.1.3 首次升级

旧版本还没有更新入口，需要手动升级一次：

1. 在设置里创建备份，从右下角托盘退出工作台。
2. 从 [发布页](https://github.com/Houraiji9/agent-workbench/releases/latest) 下载 v0.1.4 或更新的便携包，核对发布页的 SHA256，完整解压。
3. 把新包内的程序文件复制到原工作台目录，覆盖同名程序文件，保持原目录路径。保留原有 `data/`、`config/local.json`、`.agent-workbench/` 和 `.codex/`。
4. 从原位置打开工作台，核对项目与任务。此后可在设置里更新。

便携包内的 `portable-release.json` 和 `update-manifest.json` 也要一起复制。只替换 EXE 无法完成升级。

## 开发工程

源码工程以及带本机定制的开发版支持检查和下载便携包；下载后可点“打开下载文件夹”。源码由 Git 或原开发流程更新，再重新构建桌面程序。公开便携包不会自动覆盖定制工程。

## 更新失败与恢复

- 下载失败或校验失败：旧程序继续可用，重新检查并下载即可。
- 替换程序文件时遇到占用等错误：安装程序会恢复已经替换的旧文件。重新打开原位置的工作台；设置页会显示上次失败信息。
- 安装完成但新版启动异常：旧程序与安装前数据库仍在下述备份中，先保留现场，再按对应版本的恢复方法处理。
- 更新中断电：不要混用新旧程序继续工作。保留整个目录，依据安装日志和移动记录恢复；当前版本没有断电后自动修复功能。

更新下载、安装日志与上一版程序保存在 `data/updates/<本次更新编号>/`：

| 内容 | 用途 |
| --- | --- |
| 便携 ZIP | 已下载并校验的发布包 |
| previous-program | 安装前的程序文件 |
| previous-program/journal.json | 每项文件移动记录，可用于中断恢复 |
| before-update-data/workbench.sqlite | 安装前的一致数据库备份 |
| install.log | 本次安装日志 |

确认新版使用正常后，可退出工作台再清理旧的更新编号文件夹。保留最近一次备份便于恢复。更新备份含私人数据，分享问题时只提供已移除私人内容的错误说明。

## 校验与支持范围

支持 Windows 10/11 x64 官方便携版。下载时核对附件大小、SHA256SUMS 和 GitHub 提供的摘要；解包检查目录越界、链接、Windows 特殊路径与体积；安装前按清单逐个核对文件 SHA256。EXE 仍未申请数字签名，GitHub 仓库和 Release 发布权限属于更新信任边界。

v0.1.4 没有新增数据库迁移。更新界面与核心流程在隔离数据中测试；测试使用候选真实包和模拟旧版本，具体范围见 [验证记录](VERIFICATION.md)。

## v0.1.6

审查通过后增加执行者收尾，再进入用户验收；会话管理支持日常业务，关键决定在首页确认。Token Monitor 停止读取外部订阅，额度、用量和 SSE 保留。升级会执行 009—012 号迁移，已验收历史与个人订阅保留。升级前备份，回退时使用原版本程序与升级前的完整数据备份。依赖审计有一项尚未修复的 Zod 通告，详见 SECURITY.md。

## v0.2.0

本版新增简版/增量续作、按用户动作分组的待办、实时关系图，以及源码目录、运行目录和交付目标的区分。项目说明支持三行摘要和展开全文。完整变化见 [v0.2.0 更新说明](RELEASE-0.2.0.md)。

没有新增数据库迁移编号；旧执行包、审查记录及已验收历史不重写。新 Run 使用项目登记的源码目录，MCP 仍连接原安装目录的账本。需要本机安装交付时，先登记运行目录；仅完成源码或生成候选不能作为已安装证明。

当前安装证明适配工作台便携格式，绑定当前受审清单并逐文件核验。大型校验可能超过 MCP 默认等待时间，执行者应先查询正式记录；也可使用内置 `scripts/agent.ts` 的较长请求窗口，避免重复提交或把超时误判成安装失败。

完整便携升级与故障回滚在隔离数据中验证，实际日常安装更新也核对了程序清单、业务记录及连接配置。验证范围和限制见 [验证记录](VERIFICATION.md#v020-更新验证)。

## v0.4.0

新增项目收纳暂缓、文件用途与保留状态管理、项目用量和流程视图、项目默认执行策略、需求规模与审查选择，以及普通 GPT 聊天的受限规划入口。当前运行中的客户端调用不会因收纳项目而停止。原生子代理仍是指令约束，工作台不能强制控制。功能说明见 [项目管理简明指南](PROJECT-MANAGEMENT.md)。

数据库新增迁移 014，建立项目文件、文件移动、委派和用量记录表。升级前先备份。若需回退，请保留旧程序和升级前的完整备份，恢复时使用与旧程序对应的备份数据；不要把已升级的数据直接当作旧版本数据使用。此更新说明不表示某台设备已安装本版，也不表示本版已通过独立审查或用户验收。

## v0.4.5

今天页按“要做的动作”分流，待安排的例行事项改为紧凑行；需求箱的项目筛选跟随地址，侧栏返回、前进后退和刷新保持一致；项目页把说明、阶段和任务进展合在一张卡里。“更多”菜单的动作或对话框结束后，键盘焦点回到“更多”按钮。

任务详情新增“执行安排”：同一任务里可以修改执行者、主模型和子代理。还没生成执行单时直接采用；执行单已生成但没人接单时，作废这张未开始的执行单并按新安排重新生成；执行中只保存为“下一版安排”，下一次生成执行单（返修、重试、停止后重新开始）时采用，正在运行的客户端不会被热切换；失败或需要修改时直接生成下一版。每一版执行单的设置仍然冻结留档，旧交付、审查和记录不变。你的选择优先于规划建议，审查者、任务范围和验收权限不随之改变。

没有新增数据库迁移。此说明不表示某台设备已安装本版，也不表示本版已通过独立审查或用户验收。
