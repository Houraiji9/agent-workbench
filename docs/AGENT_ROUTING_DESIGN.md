# Agent 调用与有限上下文

## 责任与状态

Codex 读取规划手册、团队资源和本机能力摘要，指定执行者、独立审查者、模型路线、文件合同和返修上限。工作台从 PATH、安装登记、有限的快捷方式目录及常见目录发现客户端，核对身份与参数，保存仅属于这台机器的缓存。执行者和审查者只收到本任务入口与资料，不需要再找安装路径或读取调度手册。

外部主执行首次启动由用户在页面或客户端完成。新旧任务均默认用户控制；规划者的自动策略不等于启动授权。只有用户在任务页单独开启自动续作，后台才按计划进行自动返修或收尾；关闭许可会使旧队列失效，再开启也不恢复旧调用。大脑本人获“直接做”授权可接自己的正式 Run；执行者可直接调用独立审查和获准子代理。

客户端存在、账号可用、额度可用、调用开始、本人接单、正式结果、收尾完成和用户验收是不同事实。没有可靠来源时保留未知。程序不能根据退出码、自然语言中的 PASS 或工具 stdout 生成审查结论。

调用有持久编号、请求摘要和当前 Run 校验。重复请求返回原调用；异步发现和启动之间再次检查任务。任务取消、撤回、归档或切换 Run 会停止本程序持有的旧调用；用户也可在任务内停止当前调用。取消只处理本次持有的子进程，Windows 同时处理其进程树，保留日志并停止自动重试。

中断不会自动重新启动；已记录 PID 仍存在时阻止新调用，PID 复用也保守阻止。没有保存到进程身份的异常窗口保持未确认，任务内“中断调用恢复”要求用户核实原客户端已经结束、勾选确认并填写原因。程序保存用户声明与审计，不把声明称为已验证的进程终止。此恢复接口仅供带会话和 CSRF 的用户页面使用，执行/审查/规划 MCP 不能代为确认；原 PID 仍存在时即使用户勾选也拒绝。

已接单执行停止后，以新 Run、新会话重新开始也必须由用户页面明确选择；页面拒绝带 Agent Authorization 的混合凭据，MCP runner、planner 和 manager 不能代为重启，审计使用实际页面用户身份。重复请求保留原结果及相同权限要求。

确认恢复不会重试原执行调用。若当前 Run 已有正式 submitted 交付，且中断 execution 调用的结束已由本程序记录或由用户明确确认、没有已知会话冲突，旧中断不再阻碍独立审查。审查后的自动收尾或新 Run 自动返修同时要求用户启动许可和对应 continue_after_review、auto_rework 策略。手工接管的 failed/interrupted 调用只解除独立审查的阻碍，不转为自动主执行。未确认结束的调用仍会阻止流转；原交付、事件、产物、序号与中断记录保留。

审查可由受限审查接口回传，或由程序从本次独立客户端的原生最终输出接收绑定当前交付的结构化报告。后者必须正常退出、匹配当前 Task/Run/RA/交付摘要且没有已知会话或模型冲突。原始日志保留，两种来源分别标记；它们均不表示工作台独立验证了远端模型身份。

## 上下文与返修

计划的 `context_contract` 分别列出必读文件或行片段、满足明确条件才能补读的文件、产物目录及字节预算。工作台的文件读取接口校验 realpath、受保护目录、合同范围和累计预算；这不是对所有第三方客户端原生工具的操作系统级沙箱。客户端仍须遵守任务授权和自身安全策略，不能以合同为由绕过拒绝。

指纹只核对合同中明确命名的文件，不扫描整库；单次文件读取只核对本次明确文件，整合同快照留给上下文操作。预算按稳定合同结构累计，同 Run/RA 中修改文件内容不会重置额度，旧版缺少合同预算键的记录保守计入。已读文件改变时返回 stale 原因并继续累计。内容提供、调用者确认和模型理解分别记录。没有实测模型用量时不以字符数冒充 token。摘要变化、文件变化、上轮问题和验证结果组成返修增量。

新 Run 保留旧交付。只有同任务、同角色、同路线且上次成功调用取得真实会话编号时才请求恢复。审查增量还绑定同一个审查者和实际会话；恢复结果不符就停止自动流转，不声称已节省上下文。会话丢失时使用简版检查点，说明需要重建。

## 客户端能力边界

| 客户端 | 自动调用方式 | 本轮验证边界 |
| --- | --- | --- |
| DeepSeek Harness | headless JSONL、任务 stdin、项目内单次 overlay、原会话续接 | 适配与错误解析有测试，正式审查另留实际调用证据 |
| Claude Code | print、stream-json、默认权限、resume | 按官方参数适配；以当前机器发现和真实调用结果为准 |
| Cursor Agent CLI | print、JSON、workspace、resume | 只开放审查/建议；不默认 force 修改；路径由本机发现 |
| Grok Build | prompt-file、streaming-json、默认权限、resume | 以当前机器发现和资源采样为准，不假定额度 |

Cursor 的模型显示名称与模型 ID 分开记录。DSH 未报告实际模型 ID 时保留未知，指定的 provider/model 仅作为请求路线保存。账号、订阅和配额不会因为发现成功而变为可用；不自动切换付费路线。

## 参考与取舍

- [multi-agent-collaboration](https://github.com/Gambler134201/multi-agent-collaboration)，研究版本 `4e73c4c84ee4b46e7f5f4b3b235e0e6ee53a1fcf`：采用范围索引、短任务包、输出落盘和交付回调的思路。它的默认返修新会话方式不用于工作台的同会话复审。
- [Aider repository map](https://aider.chat/docs/repomap.html)：借鉴按需要提供代码定位信息；本轮选择显式文件/行合同，没有引入全库摘要或额外模型调用。
- [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview)：借鉴持久状态与明确交接；业务状态仍以工作台账本为准。
- [OpenHands](https://github.com/All-Hands-AI/OpenHands)：参考会话恢复与终态区分；没有引入其运行时依赖。
- [Claude Code headless](https://code.claude.com/docs/en/headless) 与 [Cursor 输出格式](https://cursor.com/docs/cli/reference/output-format)：按客户端明确输出解析，不递归解析工具内容中的 JSON。

这些项目是设计参考，不是测试通过或安全性的证明。工作台没有接入新的网页规划模型；真实模型仍负责规划与审查。


模型与档位是可选建议，由各Agent按自身客户端规则与任务需要决定。无需自报或证明型号，缺失记为未知；型号差异不阻止接单、交付或审查回传。旧模型白名单与冻结型号要求不再生效。
