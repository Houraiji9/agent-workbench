# v0.2.1：人工交接可见与审查状态一致

“待安排”中包含需要用户复制、转发给执行者或审查者的实际操作；这些步骤未完成时，工作流仍在等待用户。

- 首页待安排默认展开，唯一待办也能直接看到。
- 保留手动收起和展开；主动切换动作筛选时重新展开，避免选中“待安排”仍看不到卡片。
- 将“仅需转发的事项”改为“需要你转发或继续的事项”。
- 保留分组、搜索、排序和加载更多；复制仍不等于已发送或接单。
- 审查者真实接单后，首页、任务详情、项目列表、关系图、搜索与记录中的当前任务徽标统一显示“审查中”；未接单仍显示“已交付，待审查”。显示层结合审查阶段，不改写账本已有状态语义。

本次只修正展示默认值，不修改业务状态、权限、模型调用或更新安装边界。类型检查、构建与相关浏览器回归用于验证这些变化。

## 关于下载后只有 ZIP

正式便携版的更新包本来就是 ZIP；下载、校验和解包后，桌面版提供“重启并更新”。若只有“打开下载文件夹”，说明当前运行环境没有通过原地安装资格检查。

v0.1.4 起的检查包括：打包的 Windows x64 桌面入口、有效且版本一致的 portable-release.json、运行根目录没有 .git、程序目录无链接，以及业务数据目录不与受管程序目录重叠。旧版界面把这些失败统一写成开发版，未显示具体原因。因此仅凭 ZIP 或安装路径，不能确定是哪一项失败。

源码工程应保留 Git 和开发流程；需要日常自动换包时，使用独立的完整官方便携目录，并通过备份/恢复迁移原数据。不要删除 .git 或伪造版本标记来强行开启更新。
