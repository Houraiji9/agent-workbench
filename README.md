# Agent Workbench · 工作台

一个面向 Windows 的本地 Agent 项目管理桌面应用。把散落的项目、AI 团队、额度、需求、执行记录和成果放到一起，以中文界面管理每天的工作。

它保留你熟悉的协作方式：**提出需求 → Codex 规划 → 你启动执行 → 接收成果 → 独立审查 → 执行者收尾 → 自己确认通过或退回**。

日常待办分为待回答、待试用、异常需决定和待安排；项目页提供可展开说明与真实关系图。规划者指定执行/审查路线后，工作台发现本机客户端、记录调用并尝试续接原会话；旧任务仍保留手动入口。执行者与审查者只读取当前单据所需的范围和资料，固定回报字段由程序填写。本机交付需校验实际安装后才能交用户试用。参见 [简版工作流程](docs/COMPACT_WORKFLOW.md)。调用结束、正式交付、审查通过和用户验收分别记录。

**v0.4.6** 汇总 v0.2.1 以来的项目管理、用量、交付与界面改进，并将主执行启动、自动续作许可和子代理登记分开管理。详见 [v0.4.6 更新说明](docs/RELEASE-v0.4.6.md)。可下载版本以正式 Release 为准，实际安装版本在“设置”中查看。

## 开始使用

从 [Releases](https://github.com/Houraiji9/agent-workbench/releases) 下载 Windows 便携包，完整解压到当前用户可写的文件夹，双击 `桌面版/工作台/工作台.exe`。便携包自带运行环境，不需要安装 Node。

- 最小化：留在 Windows 任务栏。
- 关闭窗口：收进右下角托盘，后台继续运行，点击托盘图标恢复。
- 右键托盘 →“退出工作台”：结束工作台及它本次启动的数据服务。
- 再次打开：恢复本地项目与记录。请保留整个文件夹，不要只移动 EXE。
- 可选运行 `scripts/安装开始菜单入口.ps1`，创建开始菜单入口后自行固定。

系统要求：Windows 10/11 x64；需要本机可用的 4317 端口。当前是便携版，程序未签名，首次启动可能出现 Windows 信誉提示；从本仓库下载并核对发布页校验值后再决定运行。

## 第一次使用

1. 在“项目”登记自己的文件夹，或建立项目；暂时不想继续安排时可“收纳并暂缓新安排”，已结束的项目可以归档。收纳不会停止正在运行的调用。
2. 在“团队”添加需要的软件。预设库提供常见工具的资料和图标，添加后可以编辑职责和模型。
3. 在“额度”登记手动额度，或双击解压目录的 **连接Token Monitor.cmd** 接入本机额度。便携包自带本机 Hub，可选择任意安装位置；按窗口提示在 Token Monitor 填写连接地址与密钥。积分可填写月度基础、剩余及刷新日期。
4. 点击“提需求”。“先记下来”留作想法；“现在开始”交给你选用的 Agent 规划，页面提供可复制的衔接内容。普通需求优先选择能力够用的经济模型；重点需求要求明确的能力比较和完整独立审查。成果类别与使用位置按需要选择。
5. 在“设置 → Agent 客户端”查看本机检测结果，安装或换电脑后刷新。自动发现失败时才需要在高级修复中指定已安装程序路径；账号与模型是否可用以实际调用为准。
6. 在项目的“执行顺序”查看先后，在任务“执行安排”检查执行者、主模型和子代理。外部主执行默认由你启动；需要自动返修和收尾时，在“启动方式”单独开启许可。你已授权的当前 Agent 会话可以按正式执行单本人接单，独立审查按本任务安排进行。最后由你查看成果并试用确认。

首次启动只带 Codex、Claude、Grok Build 三个可编辑团队模板，以及当前工作台项目；没有账号、订阅、余额、会话或已完成任务。按自己的使用情况添加和删除即可。

## 主要功能

| 功能 | 当前支持 |
| --- | --- |
| 今日与项目 | 按待办动作分组、需求箱筛选、项目进度、收纳暂缓、文件用途与保留状态 |
| 团队与额度 | 42 项预设、自定义团队/模型、共享池、多窗口、月度积分、订阅与日程 |
| 执行单 | 步骤与前序、建议派单队列、稳定 Task/Run、真实文件包、签名回执、重试与返工 |
| 成果与验收 | 源码/软件/服务等成果档案、本机或线上使用目标、独立审查、部署证据与逐项收尾 |
| Codex MCP | 查询资源与历史、提交计划、导出执行单、按 Run 回报、安排独立审查 |
| Agent 客户端 | 本机发现与刷新、调用记录、失败原因、真实会话续接；Cursor CLI 核验后用于只读审查 |
| 执行安排 | 分阶段保存执行者、主模型和子代理选择，保留每版执行单；用户控制外部主执行启动，单独许可自动续作 |
| Token Monitor | 项目会话用量与工作台调用用量分别呈现，缺失保持未知，离线保留采样时间 |
| AgentsView | 读取会话列表/搜索/详情，关联项目与执行记录 |
| Archify | 本地图解渲染、固定项目图解入口 |
| 软件更新 | 设置中检查与下载新版，官方便携版可重启安装并保留数据 |

外部集成默认未连接，需要在自己的电脑配置。工作台可按已授权计划调用本机客户端，不代购订阅、扩大预算或绕过账号权限。客户端路径和检测结果只留在本机，公开包不携带个人配置；在另一台电脑更新后重新发现。模型目录是带日期的资料快照，后续可编辑。

项目用量只统计能明确关联的记录；Token Monitor 会话与工作台调用可能重叠，不能相加。API 等价估价不是订阅实际扣款。项目流程、客户端会话和子代理分别保留来源，未知归属不会按项目名猜测。

交付档案区分“成果是什么”和“在哪里使用”。工作台便携程序按安装清单核验；其他本机或远程部署可以保存执行者报告的证据，并明确标注来源。任务的普通/重点要求、模型选择和用户指定的交付目标不会因规划而静默改变。

v0.1.4 起可在“设置 → 软件更新”检查、下载和安装新版；更早版本首次需手动升级，详见 [更新说明](docs/UPDATES.md)。

## 如何交给其他 Agent 审查

规划者为任务选择独立审查者与调用路线。交付后，已启用的自动审查会按当前计划调用审查者；任务详情显示调用、接单与报告状态。正常审查无需你转发。客户端缺失、账号/权限受阻或需要你的决定时，页面显示实际原因。

本机 Agent 完成后，完整报告会附到任务。需要修改时保留旧成果，建立后续执行单；审查通过后由执行者完成收尾，再由你试用确认。自动返修和收尾同时受任务计划与用户的“启动方式”许可约束，修改安排或审查完成本身不构成启动授权。纯网页客户端无法读取本机资料，或你明确选择手动处理时，可展开“手动转发或导入审查”，使用复制入口与回执导入；复制不代表已发送或已接单。

允许的子代理通过本 Run 的固定入口先登记模型、读写范围和产物，再报告实际会话与结果；子代理不充当作者自身的独立审查。原生客户端内部的子代理仍是指令约束，工作台不承诺强制拦截或完整观测。

## 从源码启动

安装 Node.js **24+**、npm 和 Git，在项目目录运行：

```powershell
npm ci
npm run desktop:build
.\启动工作台.ps1
```

退出用右键托盘菜单“退出工作台”，或 `停止工作台.ps1`。源码开发可用 `npm run dev` 启动本机后台、`npm run build` 构建页面。日常使用建议桌面入口；开发后台与桌面版不要同时占用相同端口。

```powershell
npm test
npm run test:e2e
```

页面测试默认使用 Chrome，测试数据放在独立临时目录。没有 Chrome 时先 `npx playwright install chromium`，再设置 `$env:PW_CHROMIUM='1'`。所有测试夹具均为模拟数据。

## 数据和备份

项目列表、任务、订阅和额度存于本地 `data/`；各项目的执行包存于 `.agent-workbench/`；本机设置位于 `config/local.json`。这些目录不进入公开仓库。移动已有项目后请核对登记路径；便携程序移动不等于迁移外部项目。

在设置中创建备份。备份包含账本、成果副本、执行包和本地凭据，应在私人位置保管。恢复仅写新目录，具体见 [使用与维护](docs/USAGE.md)。软件不提供云端同步或操作系统级隔离，其他能读取你文件夹的本机用户也可能读取这些数据。

从 v0.2.1 升级到本版本涉及 **013、014 号数据库迁移**，增加客户端调用、项目文件与移动记录、委派和用量记录。安装前保留完整数据备份和旧程序；便携更新应保留本机配置、账本及执行包。回退时使用对应旧程序和升级前备份，不把升级后的数据库直接交给旧版本使用。安装与回退步骤见 [更新说明](docs/UPDATES.md)。
